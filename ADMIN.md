# ApexLoad administration

The verified owner account is recorded by UUID in `admin_members`. Users cannot edit this table or grant themselves a role. Account → Admin dashboard opens `/admin`; all admin routes require both an active account and database admin membership.

## Configuration

- Apply `supabase/migrations/0016_admin_and_feedback.sql` before running the updated app.
- Set `SUPABASE_SERVICE_ROLE_KEY` in the server environment only. Never prefix it with `NEXT_PUBLIC_`.
- `NEXT_PUBLIC_APP_URL` optionally overrides the live URL used for invitation callbacks. Use the canonical production URL in production.
- Supabase Auth must allow the live `/auth/callback` redirect. Configure custom SMTP for invitations to recipients outside the Supabase project team. Native Supabase email delivery failures are reported as failed invitations rather than success.

## Behavior

- The regular app is the default after sign-in. Admin access is an additional Account option.
- Invitations create regular accounts; setup links set a password and activate access. Revocation and acceptance lock the same invitation row. The application invitation expires in seven days; the Auth email link may expire sooner according to Supabase settings.
- Resend emails an implicit sign-in link for an existing pending account, including when its email was verified but setup was not finished. It never creates another account. Existing active accounts are managed from Members, not invited again.
- Pending, revoked, and paused accounts are blocked by restrictive database policies, including already-issued JWTs. Workout data is preserved.
- Screenshots are limited to PNG/JPEG/WebP, 3 MB in the application, in a private storage bucket. Only admin-authorized routes issue five-minute signed viewing URLs. Feedback includes a normalized route, platform, and app version; it does not automatically collect session contents or credentials.
- Shared templates copy into a user's own templates transactionally. Editing a shared template never changes existing personal copies.
- Feature controls govern actual feedback, shared-template, and announcement availability. There are no placeholder feature switches.
- Activity entries are generated by database triggers. Ordinary users cannot forge admin entries by modifying their profile or custom exercises.

## Verification

Run `npm test`, `npx tsc --noEmit --incremental false`, and `npm run build`. Stop the dev server before building. Preview only on ports 3000 or 3001 for OAuth compatibility.

Verify owner access; ordinary-user denial of `/admin` and `/api/admin`; screenshot privacy; draft visibility; template copying; invitation setup/revocation; and direct database denial for paused accounts. Do not send test invitations to real recipients without permission.
